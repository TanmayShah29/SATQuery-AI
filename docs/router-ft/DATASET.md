# Data card: SatQuery router dataset

Status: **built 2026-10-28** by `ml/router_ft/auto_dataset.py`. Every number below names
the file it comes from. All labels are **silver** (model-made); no person wrote or checked them.

## Purpose

Training and evaluating a router that maps a satellite-imagery query plus two UI
context hints to a routing decision (schema v1.0, [GUIDELINES.md](GUIDELINES.md)).

## Training pool: automatic check

Source: `data/router_ft/reviewed.jsonl`.

| | count |
|---|---|
| candidates generated | 1,060 |
| kept (checker's label identical) | 657 (62%) |
| rejected: checker disagreed | 396 |
| rejected: invalid proposal | 7 |

**Checker change.** `gpt-oss-20b` (Groq) was the checker until Groq's free 200K tokens/day cap
stalled the run after 467 candidates. Nemotron Ultra then re-checked **all** candidates, and only
its checks decide what is kept. On the 444 candidates both labelled
(`results/router_ft/checker_agreement.json`):

| Metric | Value |
|---|---|
| labels identical | 292 / 444 (66%) |
| intent agreement (kappa) | 0.930 (0.914) |
| raw agreement: secondary / entities / temporal / cloud | 0.901 / 0.831 / 0.914 / 0.984 |
| kept by gpt-oss-20b / by Nemotron / by both | 277 / 284 / 234 |
| same keep-or-reject decision | 79.1% |

So about one candidate in five would have a different fate under the other checker. Which
model checks is a real choice, not a detail.

## Known biases and limitations

- **No human wrote or checked any label.** Test labels are the cases where two models
  agreed, so ambiguous queries are filtered out and the test set is likely **easier** than
  real traffic. Any convention both labellers share is invisible to it.
- **The hardest slice is thin.** Only 35% of `hint_driven` test candidates survived the
  agreement filter (14 rows), and training has 23. Per-slice numbers for `hint_driven` will
  have wide confidence intervals.
- **Training never shows a query with no entities**, while 20 test rows have none. A
  fine-tuned model may over-predict entities; watch the entities field in evaluation.
- **No row has both pairs available** (`both` hint configuration). Out of scope for this data.
- **Machine-written queries.** Test and train come from different models and prompts, but
  both reflect an LLM's idea of how analysts type. There is no real user traffic.
- **The training checker changed mid-build** (see above); the kept set reflects Nemotron
  Ultra's judgement.
- **Hint distribution is set by hand** (mostly `cross_modal`, matching the API default), not
  measured from production.
- **English and Hinglish only**, Latin script. Devanagari input is not covered.
- **Indian place names dominate**, by design of the generator prompt.
