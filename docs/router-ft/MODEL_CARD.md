# Model card: satquery-router (Qwen2.5-1.5B-Instruct + LoRA)

## Summary

A LoRA adapter for `mlx-community/Qwen2.5-1.5B-Instruct-4bit` that turns a satellite-imagery question and
two UI hints into SatQuery's routing decision (schema v1.0). It is an optional replacement for the regex
`AgentRouter`, used with the regex router as fallback (`ROUTER_BACKEND=llm`, see [SERVING.md](SERVING.md)).

| | |
|---|---|
| Base model | Qwen2.5-1.5B-Instruct, MLX 4-bit (`mlx-community/Qwen2.5-1.5B-Instruct-4bit`), Apache-2.0 |
| Adapter | LoRA rank 8, scale 20, last 16 of 28 layers, all attention and MLP projections; 5.3M trainable params (0.34%) |
| Checkpoint | step 700 of 800 (micro-batches), chosen by val exact match |
| Files | `ml/router_ft/adapters/qwen1.5b-r8-best/` (git-ignored, about 21 MB) |
| Serve | `mlx_lm.server` with base + adapter, unmerged (merging/re-quantising was not validated for this model) |

## Intended use

Routing English or Hinglish (Latin script) questions about satellite imagery in the SatQuery app: which
specialist pipeline to run (change detection, optical/SAR fusion, SAR or optical question answering,
grounding, captioning), which object categories are involved, what time span, and whether cloud piercing is
needed. Always behind a validator and the regex fallback; a decision that fails schema v1.0 is not used.

**Not for:** anything outside this schema; Devanagari input; decisions where a wrong route is costly
without a human in the loop.

## Input and output

Prompt (exactly as trained; the backend's `llm_router.py` is checked against it in tests):

```
system: You route queries for a satellite-imagery assistant. Reply with only the JSON routing decision.
user:   Hints: {"has_bitemporal_pair": false, "has_sar_pair": true}
        Query: <the user's question>
        Return only the JSON label.
```

Output: `{"intent": ..., "secondary_intents": [...], "entities": [...], "temporal": "<a> -> <b>" | null,
"cloud_piercing_required": bool}`. Vocabulary and rules: [GUIDELINES.md](GUIDELINES.md).

## Training data

677 chat examples: 564 training rows generated by `openai/gpt-oss-120b` and kept only where an independent
checker model (`nvidia/nemotron-3-ultra-550b-a55b`) produced the identical label, plus 113 rule-derived
bitemporal-mode copies. 112 val examples built the same way. No human labels. Data card:
[DATASET.md](DATASET.md).

## Training

mlx-lm 0.32.2 on an 8 GB Apple M1: Adam, learning rate 5e-5, batch 4 with 2-step gradient accumulation,
800 micro-batches (about 4.7 epochs), loss on the answer tokens only, gradient checkpointing, seed 0. About
92 minutes. Config: `ml/router_ft/lora_config.yaml`.

## Evaluation

On a frozen, silver-labelled test set of 189 queries (two-model agreement, written before any training
data existed), run once. Full tables in [RESULTS.md](RESULTS.md) and [BASELINES.md](BASELINES.md).

| | exact match [95% CI] | intent acc | valid output | p50 latency (8 GB M1) |
|---|---|---|---|---|
| this model alone | 59.8 [52.4, 66.7] | 79.9 | 89.9 | 1.8 s (in-process) |
| this model + regex fallback (deployed) | 65.1 [58.2, 72.0] | 87.3 | 100 | 3.4 s (via server) |
| regex AgentRouter | 31.7 [24.9, 38.1] | 61.9 | 100 | 0.17 ms |
| same base, prompted with rules + 12 examples | 16.9 [12.2, 22.8] | 30.7 | 61.9 | 10.0 s |

## Limitations and risks

- **Silver labels**: test accuracy is agreement with two LLM labellers on queries they agreed on, likely
  easier than real traffic. No human verification.
- **About 10% invalid outputs** (off-vocabulary entities, cloud piercing without fusion); the deployed
  system falls back to regex for these. No constrained decoding yet.
- **Over-predicts entities** (extra `vegetation`/`building`; only 8 of 20 no-entity queries got an empty
  list) and misses implied cloud cover.
- **Weaker on paraphrases** (51.2% deployed) than on other slices.
- **Quantisation-sensitive**: evaluated only as 4-bit MLX base + unmerged adapter. Other runtimes or merged
  exports must be re-validated (a 3B QLoRA sibling lost 9–21 points that way).
- **Memory**: on 8 GB machines it competes with other local models; under that pressure requests time out and
  fall back to regex.
